## 2. 架构与请求链路

```
学生点击「开始诊断」
   ↓  POST http://127.0.0.1:8000/api/code-diagnose
   ↓  { code, language, run_result? }
FastAPI(main.py)
   ├─ 入参校验（空代码 / 超长 → 400 友好提示）
   ├─ messages = [SYSTEM_PROMPT, build_user_prompt(...)]
   ├─ llm_service.deepseek_client.chat()  ← 唯一 HTTPS 出口，密钥仅在此处
   │      · 超时 60s，瞬时错误重试 1 次
   │      · 上游不支持 response_format 时自动降级文本模式
   ├─ parser.parse_levels() 宽松解析（JSON / 围栏 / 中文键 / 纯文本分级）
   │      失败 → fallback_levels() 仍返回完整三级结构（degraded=true）
   └─ build_frontend_payload() 转前端原有契约
   ↓  { success, data: { error_type, total_levels, levels, direct_answer } }
前端 renderLLMGraded() 沿用原布局渲染（层级 tab / 上下一级 / 帮忙改错 / 直接看答案）
   ↓ 任何失败（超时 / 5xx / 断网）→ 顶部黄色提示 + 自动降级本地知识库诊断
```

**密钥安全**：`DEEPSEEK_API_KEY` 只出现在后端内存与请求头，前端 HTML 中没有任何密钥；
接口响应与日志一律脱敏（`sk-a****9f2c`）。

**职责边界**：`llm_service/` 只负责「发请求 + 取文本」，不含业务判断；
bug 识别、分级、讲解内容全部由系统提示词约束模型完成，后端只做解析与兜底。

## 5. 前端改动（仅 3 处，均在 `llmDiagnose` 及相邻位置）

1. **请求体换新契约**：`{ code, language: "python" }`（原 `{source_code, command}` 不再使用）；
   第二个输入框（运行结果/报错信息）非空时作为 `run_result` 一并上传；超时 30s → 60s。
2. **错误信息透出**：非 2xx 先读响应体 `detail`，让「诊断服务暂不可用，请稍后重试」直达用户。
3. **新增 `llmFriendlyError(err)`**：`AbortError` →「诊断服务响应超时，请稍后重试」；
   `Failed to fetch` / `NetworkError` →「无法连接诊断服务，请确认后端已启动（URL）」。

**未新增任何输入框、未改布局样式、未改模式开关**——严格遵守「不改 UI」。
前端 UI 无「编程语言 / 题目要求」输入框，故 `language` 固定传 `python`；
`problem` 后端接口已支持，用 curl 或后续加输入框即可生效。

## 6. 接口契约

### 6.1 请求

```http
POST /api/code-diagnose
Content-Type: application/json

{
  "code": "nums=[3,1,2]\nprint(nums[3])",
  "language": "python",
  "problem": "输出列表最后一个元素",
  "run_result": "IndexError: list index out of range"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `code` | ✅ | 学生代码，上限 `MAX_CODE_LENGTH` |
| `language` | | 默认 `python`；支持 java / cpp / c / javascript / go 等别名归一 |
| `problem` | | 题目要求（可选，越具体诊断越准） |
| `run_result` | | 运行结果或报错（可选，用于提取 `error_type`） |

兼容旧字段：`source_code`/`content` ≙ `code`，`lang` ≙ `language`，
`problem_statement`/`requirement` ≙ `problem`，`error_message`/`command` ≙ `run_result`。

### 6.2 成功响应（200）

```json
{
  "success": true,
  "source": "llm",
  "model": "deepseek-v4.1-flash",
  "language": "Python",
  "elapsed_ms": 5120,
  "degraded": false,
  "data": {
    "error_type": "IndexError",
    "total_levels": 3,
    "levels": {
      "1": { "hint_text": "看索引取值：列表长度 3，合法下标 0/1/2。", "fix_code": "nums=[3,1,2]\nprint(nums[2])", "is_last": false },
      "2": { "hint_text": "取最后一个元素可以直接用 nums[-1]。", "fix_code": "nums=[3,1,2]\nprint(nums[-1])", "is_last": false },
      "3": { "hint_text": "Python 负索引从末尾计数，-1 即最后一个，越界抛 IndexError。", "fix_code": "nums=[3,1,2]\nprint(nums[-1])", "is_last": true }
    },
    "direct_answer": { "hint_text": "已直接给出完整正确代码，跳过阶梯提示，适合快速对照答案。", "fix_code": "nums=[3,1,2]\nprint(nums[-1])" }
  }
}
```

- `levels` 的键始终连续（`"1"…"n"`），`is_last` 只标在最后一级；
- `direct_answer` 复用最后一级完整代码，前端「直接看答案」按钮读它；
- 代码无 bug：`total_levels = 0`、`levels` 空对象、`direct_answer = null`，
  前端显示「✅ 代码运行正常，没有需要修复的 bug。」；
- `source = "llm_fallback"` / `degraded = true` 表示模型输出未解析成功，走了兜底三级。

### 6.3 异常响应

| 状态码 | 场景 | `detail` |
| --- | --- | --- |
| 400 | 代码为空 / 超长 | 「代码内容不能为空，请粘贴需要诊断的代码。」/「代码长度超过限制（最多 8000 字符）。」 |
| 502 | 上游报错（Key 无效、额度不足、模型名无权限等） | **「诊断服务暂不可用，请稍后重试」** |
| 503 | 未配置 Key / 其它未预期异常 | **「诊断服务暂不可用，请稍后重试」** |
| 504 | 上游超时 | **「诊断服务暂不可用，请稍后重试」** |

前端收到任何非 2xx 都会显示后端文案并**自动降级本地诊断**，不白屏、不弹异常。

## 7. 系统提示词与解析兜底

系统提示词（`llm_service/prompts.py`）：定位为「高校编程教学专属 AI 助教」，
强制三段式【一级讲解-启发层】/【二级讲解-方法层】/【三级讲解-原理层】，
输出严格 JSON：`{"level1":{"explain","fix_code"},"level2":{…},"level3":{…}}`，
`explain` 为纯文本、`fix_code` 为基于原代码的最小改动完整代码、三级渐进；
代码无 bug 时三级 `explain`/`fix_code` 全为空字符串；顶层不得有多余字段。

解析器（`llm_service/parser.py`）按宽松原则逐级尝试：

1. 去 ` ``` ` 围栏、去整段外层圆括号（模型偶尔写成 `({"level1": ...})`）
   → `json.loads(..., strict=False)`（容忍字符串内裸换行）；
2. 失败则截取首个 `{` 到末个 `}` 再解析；数组包裹取第 0 个元素；
   仍失败再试 `ast.literal_eval`（兼容单引号字典 `{'level1': {...}}`）；
3. 键名兼容 `level1 / level_1 / lv1 / "1" / 第1级 / 一级讲解 / levels 嵌套`；
4. 值兼容字符串、对象（`explain|hint_text|hint|text|content|detail` 与
   `fix_code|fixed_code|code|solution|answer_code`）、二元数组；
5. 完全不是 JSON 时按【一级讲解-启发层】等标记切分纯文本，并抽取 ``` 代码块作为 `fix_code`；
6. 仍失败 → `fallback_levels()`：若残留文本仍像 JSON（含 `level1/explain/fix_code` 字段名），
   先用正则按字段名把三级 `explain` / `fix_code` 捞回来，**绝不把 JSON 原文直接展示给学生**；
   捞不出来才用三级通用引导文案（永不抛错）。

字段齐全但三级全空 = 模型判定「代码没 bug」，属合法响应，不会被误判为解析失败。

## 8. 模式切换与前端状态（原有逻辑，未改动）

| 行为 | 说明 |
| --- | --- |
| 默认模式 | 大模型智能诊断（`bugmind_diag_mode`，首次默认 `llm`） |
| 自动降级 | 后端未启动 / 网络异常 / 超时 / 格式异常 → 切回本地知识库，顶部黄条提示 |

| 层级渲染 | `llmRenderLevelHtml`：提示默认可见，`fix_code` 为空时隐藏【帮忙改错】 |
| 上/下一级 | `llmNextLevel` / `llmPrevLevel`：`is_last` 时【下一级】置灰提示「✅ 已经是最后一级」 |
| 直接看答案 | `llmShowDirect`：展开/收起完整代码 |
| 无 bug 分支 | `total_levels=0` → 「✅ 代码运行正常，没有需要修复的 bug。」 |

**档案写入**：`genRecord(..., "大模型")`，与本地模式共用 schema，详情/重练/学习路线全兼容。

## 9. 排错 FAQ

| 现象 | 原因 / 处理 |
| --- | --- |
| 「无法连接诊断服务」 | 后端没启动或端口不是 8000；访问 `http://127.0.0.1:8000/health` 确认 |
| 「诊断服务暂不可用，请稍后重试」 | 上游报错/超时，看后端控制台 `大模型调用失败(code=...)`；常见为 Key 无效、余额不足、模型无权限 |
| `/health` 显示 `missing_api_key` | `.env` 不在查找路径，或 Key 值为空；放到 `Desktop\.env` 或 `后端\.env` |
| 每次都走兜底（`degraded=true`） | 看控制台 `返回内容不符合契约(...) 原文前 300 字:`；多为模型未按 JSON 输出，可降低 `LLM_TEMPERATURE` 或换模型 |
| 中文乱码（控制台） | 仅 Windows 控制台编码问题，接口返回正确；可 `chcp 65001` |
| 端口被占用 | 改 `.env` 的 `PORT`，同步改前端 `LLM_API_URL` |
| 换地址部署后前端连不上 | `LLM_API_URL` 仍是 127.0.0.1，改为实际地址 |
| `file://` 打开无反应 | 部分浏览器限制 file 跨域，改用 3.4 节 http 服务方式 |
